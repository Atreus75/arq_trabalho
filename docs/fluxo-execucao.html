⚙️ MIC-1.sim — Fluxo de Execução de um Programa React/TS ↔ HTTP JSON ↔ Motor C11

Arquitetura Cliente-Servidor Stateless: Interface Win98 → Zustand → Fetch HTTP → Servidor Socket C → Montador, Caminho de Dados (4 Subciclos) e Cache

Cenário:
1. Interface React (UI) Win98
1 - Editor.asm ATIVO
components/EditorPanel.tsx

Editor Assembly MAC-1, botões Montar, Gravar código na MP, Montar e iniciar, Tabela de Símbolos e Binário.

2 - Processador ATIVO
ProcessorPanel.tsx / InternalPanel.tsx

Contadores de Ciclos e Tempo (ms), 11 Registradores, Controles de Passo/Clock, Breakpoint e Caminho de Dados Interno.

3 - Memória & Cache ATIVO
components/MemoryPanel.tsx

Memória Principal (4096 palavras com destaque de PC e Pilha >= SP) e Aba Cache (Hit/Miss, linhas e políticas).

2. Estado & Cliente TS
Zustand Store ATIVO
store/mic1Store.ts

Guarda codigoFonte, resultadoMontagem, estadoCpu, estadoCache, _timer (clock) e breakpoint.

Cliente Fetch HTTP ATIVO
api/client.ts

Funções postJson(), assembleProgram(), simInit(), simStepMicro(), simStepMacro(), simStepSubcycle().

3. Rede Local HTTP 127.0.0.1:3001
📤 Requisição POST IDA
HTTP/1.1 application/json

Envia payload JSON stateless ({ sourceCode }, { program } ou { state, cache }) para /api/*.

📥 Resposta 200 OK VOLTA
HTTP/1.1 application/json

Devolve JSON completo com { ok: true, state: Mic1CpuState, cache: Mic1CacheState } ou AssembleResult.

4. Servidor & Protocolo C11
Servidor HTTP Socket ATIVO
simulator/src/server.c

serve_local() e handle(): aceita socket TCP local, valida Host/Origin, lê Content-Length e chama protocolo.

Despachante & JSON ATIVO
protocol.c & json.c

protocol_request(): faz parse do JSON, reconstrói structs C (state_read / cache_from_json) e serializa resposta (state_json).

5. Motor do Hardware C11
Montador 2 Passos ATIVO
assembler.c & isa.c

mic1_assemble(): separa tabelas flags (rótulos :) e vars (variáveis) e codifica as 23 instruções MAC-1.

Caminho de Dados MIC-1 ATIVO
mic1.c & microcode.c

Executa exclusivamente a ROM de 79 palavras (32 bits) em 4 subciclos: S1 (MIR), S2 (A/B/AMUX), S3 (ULA/SH), S4 (Regs/MPC).

Subsistema Cache & MP ATIVO
simulator/src/cache.c

MP de 4096 palavras + Cache (Direto, Associativo por Conjunto/Total, LRU/FIFO, Write-Through/Write-Back) no 2º ciclo RD/WR.

Dentro do Motor C (`simulator/src/mic1.c`): Os 4 Subciclos do Caminho de Dados

      

        Quando o servidor C recebe POST /api/sim/step-subcycle, /api/sim/step-micro (4 subciclos) ou /api/sim/step-macro (até MPC == 0, S1), a função subcycle(Mic1State *c) executa o hardware real microprogramado na ROM de 79 palavras (microcode.c):
      


      

        

          SUBCICLO 1 (S1)
          
1. Busca da Microinstrução

          
    
            
  • Lê a palavra de 32 bits da Memória de Controle: c->mir = MIC1_ROM[c->mpc].
    • 
            
  • Se c->mpc == 0 (início de macroinstrução), salva c->endInstrucao = PC & 0x0FFF.
    • 
            
  • Registra no trace RTL: S1: MIR <- ROM[mpc].
    • 
          

        


        

          SUBCICLO 2 (S2)
          
2. Barramentos A, B e AMUX

          
    
            
  • Decodifica campos A (bits 8..11) e B (bits 12..15) do MIR para selecionar entre os 16 registradores.
    • 
            
  • Carrega c->latchA = R[A] e c->latchB = R[B].
    • 
            
  • Multiplexador AMUX (bit 31): escolhe c->ulaA = AMUX ? c->mbrLeitura : c->latchA.
    • 
          

        


        

          SUBCICLO 3 (S3)
          
3. ULA, Flags N/Z e Deslocador

          
    
            
  • Campo ALU (bits 27..28): executa 0: ulaA + latchB, 1: ulaA & latchB, 2: ulaA ou 3: ~ulaA.
    • 
            
  • Atualiza flags N (bit 15 da saída da ULA) e Z (saidaUla == 0) antes do deslocador.
    • 
            
  • Campo SH (bits 25..26): 0: sem deslocamento, 1: >> 1 aritmético (preserva bit 15), 2: << 1.
    • 
          

        


        

          SUBCICLO 4 (S4)
          
4. Escrita, Cache/MP e MPC

          
    
            
  • Se MAR=1: c->mar = latchB & 0x0FFF.
    • 
            
  • Se MBR=1: c->mbrEscrita = saidaDeslocador.
    • 
            
  • Se ENC=1: grava R[C] = saidaDeslocador (protegendo constantes).
    • 
            
  • No 2º ciclo consecutivo de RD/WR, invoca cache_read() ou cache_write().
    • 
            
  • Avalia COND (bits 29..30) com N/Z para definir MPC = ADDR ou MPC + 1.
    •
